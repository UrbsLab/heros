\begin{abstract}
Interpretable rule-based models can expose instance-level evidence, yet their raw outputs are often too technical for end users. We study a constrained HEROS+LLM pipeline in which a large language model serves only as a translator of structured rule evidence rather than a free-form explainer. The system receives prediction output, active rules, instance values, and optional glossary entries, then produces audience-conditioned explanations for lay, clinician, and expert readers. We evaluate the approach on the held-out MUX6 test fold with two prompt conditions, yielding 300 explanations. The pipeline converts active rules into readable IF--THEN text, maps internal feature indices to feature names before prompting, and instructs the generator to describe model behavior rather than domain truth. Across all outputs, evidence precision is 1.000, evidence recall is 0.9994, evidence F1 is 0.9997, prediction--explanation agreement is 1.000, and rule coverage is 1.000. Adding glossary context improves audience-oriented judge scores but slightly increases hallucination. The results support a narrow but useful role for LLMs in explanation workflows: translating structured rule evidence into audience-appropriate language while remaining tightly grounded in the interpretable model.
\end{abstract}

\keywords{interpretable machine learning, rule-based learning, natural language explanations, large language models, explainable AI, evaluation}

\section{Introduction}
Interpretable machine learning is often motivated by settings where model outputs must be inspected, questioned, or communicated to stakeholders with different technical backgrounds. HEROS is a recent rule-based machine learning system designed to produce compact and human-readable predictive models through separate optimization of individual rules and rule sets~\cite{lipschutzvilla2025heros}. Because HEROS exposes matched rules, predicted classes, and prediction probabilities for a single instance, it provides a strong starting point for explanation. At the same time, rule outputs that are readable to machine learning researchers are not necessarily readable to clinicians, patients, or other applied users.

Large language models are natural candidates for improving the linguistic quality of explanations, but recent work shows that free-text explanations produced by LLMs are often not faithful to the underlying model behavior~\cite{atanasova2023faithfulness,madsen2024self,parcalabescu2024measuring,lyu2024survey}. That risk is especially problematic in high-stakes domains, where users may incorrectly treat a fluent explanation as a causal or factual account of reality rather than a description of what a predictive model is doing~\cite{carriero2025describe}. This motivates a narrower design goal: use an LLM only as a translator of structured evidence that has already been produced by an interpretable model.

In this paper, we present a HEROS+LLM explanation pipeline built around that constraint. The LLM does not infer reasons from scratch. Instead, it receives a structured explanation packet derived from active HEROS rules, instance feature values, model context, and optional glossary entries. The prompting strategy is audience-conditioned, but the evidence is fixed. We evaluate the system on the MUX6 multiplexer benchmark using a held-out 50-instance test split and two prompt conditions. The first condition provides prediction output, active rules, and instance values. The second adds a concise feature glossary. For each instance we generate three explanations, targeting a layman/patient, clinician/informed user, and expert/data scientist audience.

Our contribution is threefold. First, we operationalize a modular explanation pipeline that preserves the interpretability benefits of HEROS while adding audience conditioning through constrained LLM prompting. Second, we define an evaluation protocol that separates packet-grounded evidence metrics from audience-oriented judge metrics, following the distinction between functionally grounded and human-grounded evaluation~\cite{doshivelez2017rigorous}. Third, we report an empirical study showing that tightly constrained translation can maintain near-perfect evidence grounding on a held-out synthetic benchmark while revealing measurable trade-offs between contextual richness, audience fit, and safety-oriented failure modes.

\section{Background and Related Work}
\subsection{Interpretable rule-based modeling}
Rule-based learning systems remain attractive when a model itself, rather than only a post-hoc explanation, must be interpretable. HEROS belongs to the learning classifier systems lineage, but differs from earlier systems by separately optimizing individual rules and whole rule sets under distinct objectives~\cite{lipschutzvilla2025heros}. For the present study, the important property is not HEROS training itself but the form of its explanation output: for an individual instance, HEROS can identify matching rules, contradictory rules, predicted class probabilities, and whether the instance is covered by the selected model.

\subsection{Faithful natural-language explanations}
Recent work on natural-language explanations emphasizes that fluency alone is not evidence of faithfulness. Atanasova et al.~\cite{atanasova2023faithfulness} develop tests for whether generated natural-language explanations reflect changes in the underlying decision. Parcalabescu and Frank~\cite{parcalabescu2024measuring} further argue that many widely used ``faithfulness'' tests for language explanations are better understood as output-level self-consistency checks than direct measurements of internal model faithfulness. Madsen et al.~\cite{madsen2024self} reach a similar conclusion for self-explanations from instruction-tuned LLMs, showing that persuasive explanations should not be trusted by default. Lyu et al.~\cite{lyu2024survey} survey faithful explanation in NLP and highlight the central role of evidence-based and intervention-based evaluation.

These concerns are particularly relevant for our setting. We are not asking an LLM to explain its own prediction, nor to rationalize the output of a black-box classifier. Instead, we ask it to restate evidence from an interpretable model. This narrower task avoids part of the faithfulness problem, but it does not eliminate it: the LLM may still hallucinate unsupported feature meanings, overstate certainty, or convert associative rule evidence into causal-sounding prose.

\subsection{Human-centered evaluation and audience fit}
Doshi-Velez and Kim~\cite{doshivelez2017rigorous} distinguish functionally grounded, human-grounded, and application-grounded evaluation, providing a useful framework for explanation studies. More recent XAI reviews emphasize that explanation quality is inherently user- and task-dependent~\cite{kim2024human,hoffman2023measures}. In healthcare-oriented settings, this issue becomes sharper because stakeholders often want information that is actionable or causal, while many XAI methods can only describe patterns used by a predictive model~\cite{carriero2025describe}. This distinction is aligned with our prompting policy: the system is instructed to explain what the model is doing, not what is true in the world.

\subsection{Evaluation metrics for generated explanations}
Evidence-centric evaluation has become a major theme in explanation research. The ERASER benchmark formalized evidence precision, recall, and intervention-style faithfulness metrics such as comprehensiveness and sufficiency for rationalized NLP models~\cite{deyoung2020eraser}. More recently, Xing et al.~\cite{xing2025evidence} focus on evidence attribution quality in generated fact-checking explanations. We adapt the evidence precision/recall tradition to rule-based explanation packets: the explanation is rewarded for mentioning evidence features that are actually present in the active rule set and penalized when it introduces unsupported features or claims.

For subjective evaluation we use an LLM judge to proxy audience fit, drawing methodological inspiration from G-Eval~\cite{liu2023geval} while explicitly treating judge scores as supportive rather than definitive, following Huang et al.~\cite{huang2025judge}. We also monitor hallucination as a first-class failure mode, motivated by the taxonomy and benchmarking perspective of HalluLens~\cite{bang2025hallulens}.

\section{HEROS+LLM Pipeline}
\subsection{Design goals}
The system was designed around four constraints. First, the LLM should never infer model evidence from raw instances on its own. Second, only active rules should be passed to the generator for a given instance. Third, all internal feature indices must be converted to feature names before prompt construction. Fourth, the generated text should describe model behavior only and avoid causal interpretations.

\subsection{Structured explanation packets}
For each test instance, the pipeline builds a structured packet containing the predicted class and class probabilities, whether the selected HEROS model covers the instance, the active supporting and contradictory rules, the instance feature values relevant to those rules, optional rule metadata such as numerosity, accuracy, fitness, vote contribution, and training-support counts, and a model-context summary describing the number of matching rules together with whether evidence is consistent or mixed.

Each rule is converted into readable IF--THEN text before prompting. For example, an internal rule with conditions on \texttt{A\_0} and \texttt{R\_3} is rendered as a sentence such as ``If \texttt{A\_0 = 1} and \texttt{R\_3 = 0}, then predict class 0.'' Optional metadata is appended only when needed for the target audience.

\subsection{Audience-conditioned prompting}
We define two prompt conditions and three audience profiles. Condition B contains the prediction output, active rules, and instance values. Condition C adds one-sentence glossary entries for the features that appear in the active rules. The layman or patient audience receives plain language with minimal jargon and no quantitative support metadata. The clinician or informed-user audience receives moderate technical detail with concise feature--value reasoning and qualitative or rounded quantitative support. The expert or data-scientist audience receives explicit rule identifiers, exact probability information, and rule metadata when available.

The system prompt forbids unsupported feature meanings, causal language, and claims about real-world truth. It also instructs the model to acknowledge conflicting evidence when rules disagree. Confidence is verbalized differently by audience: layman explanations use qualitative bins only, clinician explanations use rounded percentages plus bins, and expert explanations receive exact predicted-class probabilities.

\subsection{Why this is translation rather than explanation synthesis}
The proposed workflow intentionally narrows the role of the LLM. The language model does not search for new evidence, summarize the full rule population, or invent domain semantics for feature names. Instead, it receives already-structured evidence and rewrites that evidence for a specified reader. This distinction is central to the scientific framing of the study: we evaluate whether an LLM can preserve packet faithfulness while improving audience fit.

\section{Experimental Design}
\subsection{Dataset and split}
We focus on the MUX6 multiplexer benchmark included with the HEROS repository. The benchmark contains 500 total instances, partitioned into 450 training instances and 50 held-out test instances. All experiments in this paper use the full 50-instance test fold as a held-out evaluation set. Because MUX6 is synthetic, it is useful for controlled proof-of-concept evaluation before moving to biomedical datasets.

\subsection{Model training and inference}
HEROS was trained on the 450-instance training split using the repository's script-first experiment framework. For each test instance, the selected model produced an explanation packet with active rules, probabilities, and model-context summaries. We then generated explanations for every combination of 2 conditions and 3 audiences, producing 300 explanations in total.

\subsection{Generation and judge models}
The generation model was \texttt{gpt-4.1-mini} with temperature fixed at 0.0. The judge pass used the same model family at temperature 0.0, but under a separate scoring prompt. We chose deterministic settings to improve reproducibility and to reduce variance from prompt sampling.

\subsection{Evaluation metrics}
Our evaluation follows the functionally grounded versus human-grounded distinction~\cite{doshivelez2017rigorous}. The primary functionally grounded metrics are Evidence Precision, defined as the fraction of mentioned evidence features that belong to the active-rule evidence set; Evidence Recall, defined as the fraction of the active-rule evidence set that is captured by the explanation; Evidence F1, the harmonic mean of evidence precision and recall; Hallucination Rate, the proportion of explanations containing unsupported features or unsupported claims; Prediction--Explanation Agreement, which checks whether the explanation remains consistent with the model prediction; and Rule Coverage, which evaluates whether the explanation reflects the key active rules.

We also report task-specific safety and calibration checks that are necessary for this setting, namely Uncertainty Acknowledgment Rate, Causal Overclaim Rate, Conflict Acknowledgment Score, and Confidence Wording Calibration.

For layman outputs we additionally compute Flesch Reading Ease and Flesch--Kincaid Grade Level as supporting readability indicators~\cite{flesch1948readability,kincaid1975derivation}.

Human-grounded metrics were approximated with an LLM judge through Audience Understandability and Audience Technical Fit.

These judge metrics are best interpreted as scalable proxies rather than replacements for human studies~\cite{liu2023geval,huang2025judge}. We intentionally do not report comprehensiveness or sufficiency in the results because the current implementation does not yet rerun HEROS under perturbation-based feature removal or keep-only conditions.

\section{Results}
Across all 300 generated explanations, the pipeline achieved mean evidence precision of 1.000, evidence recall of 0.9994, evidence F1 of 0.9997, prediction--explanation agreement of 1.000, and rule coverage of 1.000. These values indicate that the prompt-constrained LLM almost always stayed within the feature evidence supplied by the active HEROS rules. The remaining failure modes were therefore concentrated in explanation style rather than core evidential grounding: hallucination rate was 4.0\%, causal overclaim rate was 13.3\%, and conflict acknowledgment averaged 73.3\%.

Table~\ref{tab:condition-results} compares the two prompt conditions. Adding glossary context in Condition C improved both audience-oriented judge scores, but slightly worsened packet-grounded safety metrics. Audience understandability increased from 0.820 to 0.846 and audience technical fit from 0.820 to 0.835, while hallucination rose from 3.3\% to 4.7\%. Evidence recall remained extremely high in both conditions.

Audience-level results reveal a different trade-off pattern (Table~\ref{tab:audience-results}). Expert explanations achieved the strongest audience-understandability (0.900) and audience-technical-fit (0.953) scores, but also had the highest hallucination rate (7.0\%). Layman explanations were the shortest and safest overall, with a hallucination rate of 2.0\% and causal overclaim rate of 3.0\%, but they received the weakest judge scores. Clinician explanations offered the most balanced audience-fit profile, but under our lexical causal-overclaim detector they exhibited the highest causal overclaim rate (26.0\%), suggesting that concise technical summaries can still drift into over-strong causal language if not explicitly constrained enough.

The layman readability diagnostics were directionally sensible. Across layman outputs, Flesch Reading Ease averaged 63.97 and Flesch--Kincaid Grade Level averaged 8.90. These values are not substitutes for user studies, but they suggest that the layman prompt produced text that was materially simpler than the clinician and expert variants.

The condition-by-audience breakdown further clarifies the trade-offs. The safest cell was Condition B + Layman, which achieved 0.0\% hallucination and 0.0\% causal overclaim at the cost of the lowest audience-fit scores. The best audience-fit cell was Condition C + Expert, with audience understandability of 0.900 and audience technical fit of 0.951, but it also exhibited the highest hallucination rate at 10.0\%. This pattern is consistent with the broader explanation literature: richer contextualization and higher technical detail can improve plausibility and usefulness while simultaneously increasing opportunities for unsupported elaboration~\cite{madsen2024self,parcalabescu2024measuring}.

\section{Discussion}
The main empirical result is that an LLM can be used as a tightly constrained translator of rule-based evidence without materially degrading evidential fidelity on this benchmark. The strongest evidence for that claim is not the judge score pattern, but the near-perfect evidence precision, recall, F1, prediction--explanation agreement, and rule coverage. In other words, the system largely succeeded at staying grounded in active HEROS rules while rewriting them for different audiences.

At the same time, the experiment reveals why faithful explanation generation should not be framed as a solved problem. Condition C improved both audience-oriented judge scores, suggesting that even a minimal glossary helps the model produce explanations that are easier to follow and better matched to the requested audience. But the same condition also slightly increased hallucination rate and did not improve uncertainty handling. This indicates that additional contextualization can improve readability while widening the space for unsupported elaboration.

The audience results show a similarly informative trade-off. Expert explanations were best aligned with the requested technical level, which is unsurprising because the expert prompt explicitly exposes rule identifiers, exact probabilities, and metadata. Yet those same degrees of freedom make expert outputs more vulnerable to unsupported additions. Layman explanations showed the opposite pattern: they were shortest, safest, and easiest to constrain, but they did not score as highly on audience-fit because raw feature tokens such as \texttt{A\_0} and \texttt{R\_2} remain difficult to translate into genuinely intuitive language without introducing stronger domain semantics.

The conflict acknowledgment results are also notable. Even with explicit instructions about mixed evidence, the average conflict score remained well below the other packet-grounded metrics. That suggests a concrete next optimization target: future prompt revisions should allocate more of the explanation budget to summarizing rule agreement versus contradiction, especially in multi-rule settings.

\section{Limitations and Future Work}
This study has several limitations. First, the empirical evaluation is restricted to MUX6, a synthetic benchmark with binary features and relatively clean semantics. The experiment therefore validates the pipeline design, but not yet its usefulness in biomedical settings where feature names, feature types, and stakeholder expectations are more heterogeneous.

Second, the audience-oriented metrics come from an LLM judge rather than human participants. This is a practical starting point and is consistent with recent judge-model evaluation work~\cite{liu2023geval}, but such scores should not be treated as a substitute for application-grounded user studies~\cite{huang2025judge,kim2024human}. Future work should incorporate clinician and lay-user evaluations, potentially using established scales for explanation satisfaction or system causability~\cite{hoffman2023measures,holzinger2020scs}.

Third, we intentionally do not report perturbation-based faithfulness metrics such as comprehensiveness and sufficiency. Those measures are well grounded in the literature~\cite{deyoung2020eraser}, but computing them properly here requires rerunning HEROS under feature-removal and keep-only perturbations. We view that as important future work rather than something to approximate heuristically.

Finally, the current study uses a single generator family and a single judge family. A more complete evaluation should test whether the translation behavior is robust across different generation models, different judge models, and eventually across biomedical datasets where feature glossaries carry domain-specific meaning.

\section{Conclusion}
We introduced a script-first HEROS+LLM pipeline for generating audience-conditioned natural-language explanations from structured rule-based evidence. The key design choice is to treat the LLM as a translator of active rules and instance values, not as a source of new explanatory content. On the held-out MUX6 test fold, this design achieved near-perfect evidence precision, recall, F1, prediction--explanation agreement, and rule coverage across 300 explanations. The results also expose a useful trade-off: richer context improves audience-oriented scores, but can slightly increase unsupported elaboration. Overall, the study suggests that faithful explanation translation is a viable intermediate role for LLMs in interpretable machine learning workflows, and that rule-based models such as HEROS offer a particularly suitable substrate for this style of constrained generation.
