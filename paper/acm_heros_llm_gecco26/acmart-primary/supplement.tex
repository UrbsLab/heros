\textbf{Worked instance.} Consider the instance $A_0=1$, $A_1=0$, $R_0=1$, $R_1=0$, $R_2=1$, $R_3=1$. Under the ideal rule set, only $r_6$ matches, so the match set is $M=\{r_6\}$. If numerosity is 1 for every ideal rule, then the class vote totals are $V(0)=0$ and $V(1)=1$. After normalization, $P(0)=0.0$ and $P(1)=1.0$, so the predicted class is 1. This illustrates the minimal single-rule case against which denser learned HEROS match sets can be contrasted.

\section{Prompt and Judge Documentation}
The final study used versioned prompt templates and a separate judge rubric that are implemented in \path{evaluation/experiments/heros_llm/prompt_templates.py}, \path{evaluation/experiments/heros_llm/prompt_builder.py}, and \path{evaluation/experiments/heros_llm/judge.py} on the \path{llm_exp} branch. Supplementary Tables S5 and S6 summarize the parts of those prompts that are most important for interpreting the experiments.

\begin{table}[H]
\caption{\textbf{Supplementary Table S5.} Prompt structure used in the final study. The code labels \texttt{condition\_b} and \texttt{condition\_c} correspond to \emph{Experiment 1} and \emph{Experiment 2} in the paper.}
\label{tab:prompt-docs-supp}
\centering
\small
\setlength{\tabcolsep}{4pt}
\renewcommand{\arraystretch}{1.05}
\begin{tabular}{L{0.26\linewidth}L{0.66\linewidth}}
\toprule
\textbf{Component} & \textbf{Implemented behavior} \\
\midrule
Shared system prompt (\texttt{v2\_minimal}) & Explain only one prediction, use only the supplied prediction-time evidence packet, do not use the underlying algorithm name, do not add domain meaning or unseen features, describe model behavior rather than reality, acknowledge conflict when present, and end with a brief limitation sentence. \\
Layman addon & Plain language, feature names exactly as given, no rule IDs, no metadata counts, and no numeric probabilities. \\
Clinician addon & Concise feature--value reasoning with moderate technical detail, no rule IDs, and optional training-support summaries when provided. \\
Expert addon & Technical wording that may include rule IDs, exact probabilities, conflict structure, and detailed rule metadata when provided. \\
Experiment 1 (\texttt{condition\_b}) & User prompt includes predicted class, confidence wording, evidence summary, relevant instance feature values, and active rules, but no feature definitions. \\
Experiment 2 (\texttt{condition\_c}) & Uses the same packet fields as Experiment 1 and additionally includes concise feature definitions for rule-relevant features; these definitions are used only to clarify labels, not to infer extra domain meaning. \\
\bottomrule
\end{tabular}
\end{table}
